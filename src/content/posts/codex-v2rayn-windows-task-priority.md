我在 Windows 上用 Codex 跑任务时，遇到过一个规律：一旦任务开始执行吃 CPU 的脚本，Codex 就容易掉线、反复重连。排查时，我在任务管理器里发现，负责跑本地代理的 `xray.exe` 和启动它的 `v2rayN.exe`，都被标成了「低于正常」。

另一个现象是，登录 Windows 后，v2rayN 经常要等一会儿才启动。最后，这两个线索都指向了 v2rayN 的自启计划任务，不过对应的是两个独立的设置。

## 为什么先看进程优先级

在任务管理器的「详细信息」里，右键 `v2rayN.exe` 或 `xray.exe`，打开「设置优先级」，就能看到当前档位。想判断是否跟自启有关，可以退出托盘里的 v2rayN，确认它和 Xray 都已退出，再手动打开 v2rayN，对照两个进程的优先级。只关窗口可能不会结束进程。

[v2rayN 的 GitHub 讨论 #9358](https://github.com/2dust/v2rayN/discussions/9358) 里有人观察到相同的优先级变化，也有用户提到 Codex 跑高负载脚本时会断连重试。这与我遇到的现象吻合。按 [Windows 的线程调度规则](https://learn.microsoft.com/en-us/windows/win32/procthread/scheduling-priorities)，CPU 紧张时，优先级较低的线程可能等更久才能运行；子进程在未显式设定优先级时，也可能继承父进程的「低于正常」。如果 Codex 的连接正好经过 Xray，本地代理处理数据不够及时，就可能表现为超时或重连。单凭一次掉线还不能确认是这个原因，尤其是低负载时也经常断连的情况。

## 把自启任务优先级改回「正常」

打开 Windows「任务计划程序」，在任务计划程序库里找到 v2rayN 的自启任务。名称可能因安装而异，建议从「操作」里确认它指向自己的 `v2rayN.exe`，再看「触发器」是否为「登录时」。

我这里读到的任务优先级是 `7`。按 [Microsoft Learn 的映射表](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-priority)，计划任务的 `7` 对应进程的「低于正常」，`4` 对应「正常」。这两个数字是**计划任务**的设置值，不是任务管理器里的档位编号。

任务计划程序的图形界面没有直接编辑这个字段的入口。可以先导出任务 XML，保留一份原样备份，再编辑副本，把 `<Settings>` 下的这行改成：

```xml
<Priority>4</Priority>
```

导入修改后的 XML，替换原任务，保留原来的运行账户、程序路径、参数及其他设置。如果导入时提示任务重名，先确认原 XML 已备份、修改后的 XML 也已保存，再删除原任务并用同名导入。保留备份方便回退，不要让两个任务同时在登录时启动同一个程序。通过任务管理器临时调优先级也可以用于对照，但改的是当前进程，不能代替修改自启任务。

## 顺手取消登录后 30 秒的延迟

我这里同一个任务还设了登录后等待 30 秒。想让它在登录时尽早启动，可以在任务属性的「触发器」里编辑对应的「登录时」触发器，取消「延迟任务时间」；也可以在刚导出的 XML 副本里删除对应 `<LogonTrigger>` 下的 `<Delay>PT30S</Delay>`，和优先级一并修改。[登录触发器的 Delay 文档](https://learn.microsoft.com/en-us/windows/win32/taskschd/logontrigger-delay) 说明了这个字段的含义。

这里改的是**登录后额外等待多久**。设为零不代表一按电源键就启动，也不保证登录时代理已经可以连接。如果只是排查高负载断线，可以先只改优先级，把登录延迟留作另一项调整。

## 改完怎么验证

这次修改后，读回计划任务，确认优先级已从 `7` 改为 `4`，登录延迟从 30 秒改为 0。修改前后 v2rayN 的 PID 没变，修改完成时看到当前进程显示「正常」。这个读数不能替代对下一次自启的验证。

接下来可以注销再登录，先确认 v2rayN 是否按预期启动、`v2rayN.exe` 和 `xray.exe` 是否都显示「正常」，再用此前容易触发问题的同一个 Codex 任务观察是否还会重连。截至这次记录，**计划任务配置已确认，重新登录后的实际启动耗时和高负载下的连接稳定性仍待验证**。以后如果重新开关 v2rayN 的自启设置，也值得再看一眼这两个值，确认任务没有被重建并恢复旧设置。
