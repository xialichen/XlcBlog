# 南沙早报编辑指南

给在南沙居住、通勤、工作和办事的人写。读完首屏，读者应能说出今天有什么变化，以及这件事与自己有什么关系。新一期从模板起稿。11 月 7 日样稿展示消息多时的取舍和排序，11 月 23 日样稿展示消息少时的篇幅。[Markdown 模板](briefing.md) · [11 月 7 日样稿](../src/content/posts/nansha-morning-2026-11-07.md) · [11 月 23 日样稿](../src/content/posts/nansha-morning-2026-11-23.md)

## 先选题

1. 从上期截稿时间查到本期截稿时间，统一用北京时间。读区、市主管部门和公共服务运营方的原文。当地发生了值得关注的事，也可采用本地媒体或通讯社记者的一手报道。分别记下报道发布日期和事情实际发生或生效的日期。只用截稿前已公开的事实。
2. 试着用一句话写清这条消息影响谁、从什么时候起、读者可以怎样出行、办事或参与。即使无需办理，也应有一项值得知道的当地变化。接着翻上一期，长期事项再按原文链接、公告编号或“主体＋事项”回查首报和最近一次提醒。多处转载同一件事合成一条。
3. 先排影响人多、后果明显的变化，例如停运、入学安排、就医服务调整。其次排特定人群用得上的新机会，再排少数人近期要办的事。同等影响下，先写读者最早要作决定的那条。紧急安全或公共服务变更直接放头条。当天有几条值得写，就写几条。

| 候选 | 编辑取舍 |
| --- | --- |
| 公交线路公开征求意见，可能改变沿线居民的换乘 | 可以入选。指出哪一站、哪一方向受影响，标题写明「拟调整」，给反馈入口。正式实施时再写生效日和换乘办法。 |
| 公示一名拟聘人员、已选定的获奖名单、向个别当事人送达文书 | 留在采集记录。确有新岗位开放、补贴开始接受公众申请，或公共服务安排发生变化时，再报道相应事实。 |
| 采购或招标 | 一般的购标、开标、中标结果留在采集记录。居民用得上某项新服务，或本地一批经营者获得具体机会时，写清谁受益、如何使用或参与。 |

## 写成读者能扫读的早报

- 把首屏的 `description` 当导读。最重要的一条放进模板的 `briefing-lead`，用二级标题写清「哪条线改了」「哪些人能领」「什么时候开放」。部门发文的全称留给来源链接。
- 后续消息能按读者需要归在一起时，在 `briefing-section` 里用二级标题写栏目、三级标题写各条消息。网站据此生成目录和手机栏目跳转。短报的独立消息用普通二级标题，直接接在头条后面。
- 一条通常写两三句。首句给新事实，随后写影响或下一步。数字留能帮助判断的，如最高气温从多少降到多少、哪一站可以换乘。把来源链接放在它支持的段末，沿用模板的 `<small class="briefing-source">`。网站会把来源另起一行。
- 核对行政区、适用人群和当前阶段。广州全市预报写「广州」，方案征求意见保留「拟」，已生效才写「开始」。办理时间写月日，有明确时刻就保留。相对期限沿用官方起算条件。原文只有标题、关键对象或时间无法核实的，留待后续核实。
- 某个栏目没有入选事项就整段删除。只有办理提醒时，直接从「办事提醒」开始。连提醒也没有时，可以只用一句话说明截至何时、在已核实范围内未见值得刊载的变化。部分来源无法核对时，说明具体缺口。

## 旧事项什么时候再提

**内容有实质变化**时，说明原来怎样、现在怎样，以及读者要改做什么。延期、取消、换地点、资格扩大都可能值得跟进。窗口照常开放期间，把原有安排留在采集记录。

**到了需要行动的那一天**，才考虑在文末给一次短提醒。例如周日已介绍周一的人社接访，周一只留时间、地址、携带材料和原文。若必须提前预约或备材料，就选读者最迟该准备的那一期。同一办理节点只作一次临近提醒。已在头条讲清的动作，文末省去。

「办事提醒」默认选当天或次日最有用的 **0–2 项**，按办理先后排。逐项记下原文标识、办理动作与节点日期，再与往期对照。持续多日的领取窗口视为一个节点，购标和提交响应是两个不同的动作。采购公示期结束、向特定人送达文书等日期一般只进采集记录。

每项提醒用一个列表项。第一段的 `time` 写办理时间，第二段空一行、缩进两格，写要办的事和入口。两段在宽屏上分列，手机上按先后顺序阅读。只有日期时，`datetime` 填当日的 `YYYY-MM-DD`。

## 交稿前

1. 将模板复制到 `src/content/posts/nansha-morning-YYYY-MM-DD.md`，同日改稿沿用原文件。替换全部占位符和示例链接。保留 `format: briefing` 和 `briefingLayout: digest`，可预览的正式文章使用 `draft: false`、`sample: false`。
2. 逐条打开所引原文，对照标题和摘要里的对象、数字、时刻、关键条件。再读一遍当天和上期标题，删掉失效提醒、重复节点和空栏目。
3. 用本期真实采集记录生成文末的 `nansha-report-metadata`。改写已有一期时，保留原采集窗口、核验记录、未覆盖范围和采集水位。政务新增按原采集口径统计，另采的本地新闻单记 `local_news_items`。正文来源写入 `sources`，已核实但只作记录的来源可放 `collection_only_sources`。提醒展示数按实刊事项填写，未知的候选总量用 `null`。将每条临近提醒记入 `reminder_selection.items`，如 `{"source_id":"11112920","action":"现场接访","node_date":"2026-11-23"}`。旧稿缺少这份明细时，查它的正文。
4. 定稿后重算 `report_body_sha256`。将换行统一为 LF，对元数据注释起点 `<!-- nansha-report-metadata` 之前的全部文字按 UTF-8（无 BOM）计算 SHA-256，包括 frontmatter 和结尾空行。预览页面，确认首屏导读、目录和来源链接指向本期内容。
